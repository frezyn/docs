---
title: "Withdraw Your noob-exchange Yuan Balance via PIX Key"
sidebarTitle: "Withdraw Funds"
description: "Request a withdrawal of your yuan balance to any PIX key using POST /v1/withdrawals. Funds are converted to BRL at the current quote."
---

Once you have a yuan balance from confirmed payments, use `POST /v1/withdrawals` to convert it to BRL and send it to any valid PIX key. The conversion uses the live BRL/yuan quote at the time the withdrawal is processed.

<Steps>
  <Step title="Check Your Balance">
    Before requesting a withdrawal, verify you have sufficient yuan available.

    ```bash
    curl https://api.noob.exchange/v1/balance \
      -H "Authorization: Bearer nox_your_api_key"
    ```

    **Response**

    ```json
    {
      "yuan_balance": 100
    }
    ```

    Only the yuan shown in `yuan_balance` is available for withdrawal. Any yuan reserved by a pending withdrawal is already excluded from this figure.
  </Step>

  <Step title="Check the Current Quote">
    Fetch the current BRL/yuan exchange rate to estimate how much BRL you will receive.

    ```bash
    curl https://api.noob.exchange/v1/quote \
      -H "Authorization: Bearer nox_your_api_key"
    ```

    Use the returned `quote` to calculate your estimated payout:

    ```
    value_real = yuan_value / quote
    ```

    For example, withdrawing 50 yuan at a quote of 1.2 yields approximately **41.67 BRL**. The final rate is locked at processing time, so the actual BRL amount may differ slightly if the quote moves between this check and settlement.
  </Step>

  <Step title="Request Withdrawal">
    Submit the withdrawal with the yuan amount and your destination PIX key. Any PIX key type is accepted (CPF, CNPJ, phone, email, or random key).

    ```bash
    curl -X POST https://api.noob.exchange/v1/withdrawals \
      -H "Authorization: Bearer nox_your_api_key" \
      -H "Content-Type: application/json" \
      -d '{"yuan_value": 50, "pix_key": "user@example.com"}'
    ```

    **Response**

    ```json
    {
      "id": "dbb54c30-7325-4805-a787-5a4ae98581e7",
      "yuan_value": 50,
      "value_real": 41.67,
      "quote": 1.2,
      "pix_key": "user@example.com",
      "status": "pending"
    }
    ```

    | Field | Description |
    |---|---|
    | `id` | Unique identifier for this withdrawal request. |
    | `yuan_value` | Yuan amount deducted from your balance. |
    | `value_real` | Estimated BRL amount to be sent to your PIX key. |
    | `quote` | BRL/yuan rate used for the conversion estimate. |
    | `pix_key` | Destination PIX key you provided. |
    | `status` | Current status of the withdrawal (`pending` on creation). |
  </Step>

  <Step title="Track the Withdrawal">
    After submitting, poll `GET /v1/withdrawals/{id}` or watch for a webhook notification to detect status changes.

    ```bash
    curl https://api.noob.exchange/v1/withdrawals/dbb54c30-7325-4805-a787-5a4ae98581e7 \
      -H "Authorization: Bearer nox_your_api_key"
    ```

    The `status` field reflects the current stage of your withdrawal:

    | Status | Description |
    |---|---|
    | `pending` | Awaiting processing. Yuan is reserved. |
    | `paid` | BRL has been sent to your PIX key. Withdrawal is complete. |
    | `rejected` | Request was declined. Reserved yuan has been returned to your balance. |
  </Step>

  <Step title="List Past Withdrawals">
    Review your full withdrawal history with a single call.

    ```bash
    curl https://api.noob.exchange/v1/withdrawals \
      -H "Authorization: Bearer nox_your_api_key"
    ```

    The response returns a paginated array of withdrawal objects, ordered by creation date (most recent first). Use this to reconcile your records or surface past transactions in your dashboard.
  </Step>
</Steps>

<Warning>
  Yuan is **reserved immediately** when you submit a withdrawal request and is unavailable for other withdrawals while the request is pending. If the withdrawal is rejected, the reserved yuan is automatically returned to your balance.
</Warning>

<Note>
  Withdrawal limits: **1 to 100,000 yuan** per request, with a maximum of **10 withdrawal requests per hour**. Requests outside these limits will be rejected with a `422` error.
</Note>
